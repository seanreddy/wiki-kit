Config Registry

Every tuning knob that matters, verified against source

Every toggle and variable in this project worth knowing about lives in exactly one file: a constant a programmer edits in source, or a value in tokens.yaml. This page is neither of those — it is a generated INDEX pointing at both, and unlike a page someone writes by hand, it is verified at generation time: every entry's file must exist and a literal symbol must appear in it, so a renamed or deleted knob fails the build instead of quietly going stale here.

This page has no edit control and no write path. The How to change column names the file to open and, typically, the test suite to run after — changing a knob still means editing that file by hand. This page is the evidence a debug panel would eventually need, not the panel itself.

Adding an entry

Add a key under the right area in config_registry.yaml — or a new top-level area, if none of the existing ones fit. Every entry needs name, where, symbol, scope, how, and exactly one of default (prose you write) or token (a dotted tokens.yaml path resolved live). Pick token whenever the value truly lives in tokens.yaml — it cannot go stale the way a hand-typed default can.

Regenerate after editing. If symbol does not appear verbatim in where, or where does not exist, generation fails naming the entry — fix the pointer, not the check. The manifest file's own header documents the minimal YAML subset it must stay inside (no anchors, no multi-line scalars, and & * > | are rejected even inside quotes).

How this page is built

Generated from config_registry.yaml by this pack. Prose values are exactly what a curator typed; token values are read live from tokens.yaml through the same resolver every {{token}} on this site uses. Edit the manifest, not this page — this page is output.
